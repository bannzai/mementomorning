# 0001. インフラ構成はローカルのみ (SwiftData) + RevenueCat とし、バックエンド・Firebase を持たない

## Status
Accepted (2026-08-13)

## Context
Memento Morning は毎朝の回答(テキスト)をローカルに蓄積する目覚まし + ジャーナルアプリで、RevenueCat Shipaton 2026(締切 2026-09-30)への提出を前提に約 2 週間の最小構成で作る(企画の経緯: https://github.com/bannzai/ideamemo/issues/187 )。

決めるべきは DB・ストレージ・ホスティング・認証・Analytics の構成。データはユーザー個人の回答テキストのみで、ユーザー間の共有・サーバー側処理は MVP に存在しない。

## Decision
- **DB / ストレージ**: SwiftData によるローカル保存のみ。サーバー DB・クラウドストレージは持たない
- **ホスティング / バックエンド**: なし。法務ドキュメント等の静的ページのみ GitHub Pages で配信する
- **認証**: なし(アカウントレス)。ログイン・サインアップ画面を作らない
- **課金**: RevenueCat(Shipaton の必須要件でもある)
- **Analytics / クラッシュレポート**: MVP では導入しない。Firebase / GCP を使わないため、GCP 課金・エラーアラートの整備は対象外

## Consequences

**良い点:**
- サーバー運用・認証・プライバシー対応のコストがゼロになり、2 週間スコープに収まる
- 「回答が端末の外に出ない」ことをプライバシーポリシーで明確に言える(内省日記という機微なデータと相性が良い)
- GCP アラート・Slack 緊急通知などの運用基盤が最小で済む

**悪い点 / 引き受けるリスク:**
- 端末変更・削除でデータが消える。iCloud バックアップ(SwiftData + CloudKit ミラーリング)やエクスポートは将来の課題として issue 管理する。「一生プラン」の「死後も残るエクスポート保証」を売る前にエクスポート機能が必須になる
- Analytics がないため、共有到達→DL→課金転換の計測(Most Viral 賞の応募ストーリー)は App Store Connect / RevenueCat のダッシュボード数値に頼る。不足が判明した時点で導入を再検討する
- 将来サーバーが必要になった場合(問いのデッキ配信等)は別 ADR で決め直す
