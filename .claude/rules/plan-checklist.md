# Plan ファイルチェックリスト

Plan mode でプランファイルを作成する際、以下のチェックリストをプランファイル末尾に追記すること。取り込み元: bannzai/Alarmy の同名ルール。

## ルール
- 変更対象に応じて該当セクションのみ含める
- チェック項目は `- [ ]` 形式で記載
- プランには必ず変更対象ファイルごとに具体的な実装コード提案（コードブロック）を含めること

## チェックリストテンプレート

以下をプランファイル末尾に追記する。

---

## チェックリスト

### 実装内容
- [ ] 変更対象ファイルごとに具体的なコード提案をコードブロックで記載している
- [ ] 既存コードのパターン・構成を確認し、同じパターンで実装している
- [ ] 変更範囲が必要最小限であること

### ビルド・テスト（ビルドシステムに変更がある場合）
- [ ] ビルドが成功する
- [ ] 既存テストが全件パスする
- [ ] 新規・変更機能に対するテストが存在する（なければ新規作成）

### iOS / SwiftUI（Swift コードに変更がある場合）
- [ ] シミュレータビルドが成功する（ログは ./tmp/build.log に保存し全文を warning / error で検査する）
- [ ] ユニットテストが全件パスする（時刻依存ロジックは Date 注入でテストする）
- [ ] AlarmKit API は `#available(iOS 26.0, *)` でガードされている
- [ ] SwiftData モデルの変更は `.claude/rules/swiftdata-guidelines.md` / `.claude/rules/coding-rules-entity.md` に準拠している

### 動作確認（UI・挙動に変更がある場合）
- [ ] AGENTS.md の「検証方法」に従い、/ios-simulator 経由 (simtunnel) のシミュレータで動作確認する
- [ ] UI 変更はスクリーンショットで描画を確認してから完了報告する
- [ ] アラーム発火の確認は「1〜2分後のアラーム」で行う（シミュレータの時計は変更できない）
- [ ] シミュレータの発火確認は画面表示で判定する（sound は `.default` だと鳴らない癖がある）

### 共通
- [ ] エラーメッセージはそのまま表示（加工・プレフィックス除去なし）
